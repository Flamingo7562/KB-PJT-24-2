# SPEC-247-01: 지원 은행 코드 20종 확장

## 추가 사항

지원하는 canonical `bankCode`와 사용자 표시 은행명을 다음 20개로 확장한다.

| `bankCode` | 은행명      |
| ---------- | ----------- |
| `004`      | 국민은행    |
| `088`      | 신한은행    |
| `020`      | 우리은행    |
| `081`      | 하나은행    |
| `011`      | 농협은행    |
| `003`      | 기업은행    |
| `090`      | 카카오뱅크  |
| `092`      | 토스뱅크    |
| `089`      | 케이뱅크    |
| `032`      | 부산은행    |
| `031`      | DGB대구은행 |
| `131`      | iM뱅크      |
| `034`      | 광주은행    |
| `023`      | SC제일은행  |
| `027`      | 씨티은행    |
| `002`      | KDB산업은행 |
| `007`      | 수협은행    |
| `045`      | 새마을금고  |
| `048`      | 신협        |
| `071`      | 우체국      |

- 기존 `004`, `088`, `020`, `081`, `011`의 API 값은 유지한다.
- `131`은 화면에서 DGB대구은행과 iM뱅크를 서로 다른 선택지로 제공하기 위한 프로젝트 전용
  canonical 코드다.
- 코드표는 합성 Mock 계좌 시연 계약이며 실제 금융기관 연동이나 외부 기관 코드의 정확성을
  보장하지 않는다.
- 은행명은 사용자 표시값이고 API에는 코드표의 숫자 3자리 문자열만 허용한다. 기존과 같이
  영문·한글 별칭을 API 값으로 허용하지 않는다.
- 요청 Body, 계좌번호·금액·PIN 검증, DB 컬럼과 최소 호환 스키마는 변경하지 않는다.

## 완료 조건

- [ ] 은행 선택 화면에서 위 20개 은행명이 정확히 표시되고 각각 고유한 3자리
      `bankCode`에 대응한다.
- [ ] 기존 5개 `bankCode`를 사용하는 요청의 의미와 처리 결과가 유지된다.
- [ ] 충전과 출금 요청이 확장된 코드표의 값을 허용하고 코드표 밖 값이나 은행명 별칭을
      `400 VALIDATION_ERROR`로 거부한다.
- [ ] 요구사항, API, 결정, 추적성, 릴리스 기록과 `SPEC_LOCK.json`이 같은 정식 명세
      릴리스에서 일치한다.
