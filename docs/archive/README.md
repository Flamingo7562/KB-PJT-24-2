# 문서 아카이브

`docs/archive/`는 과거에 Git으로 공유했지만 더 이상 현재 구현과 작업 절차를 설명하지 않는 문서를 보관합니다. 현재 개발 기준과 문서 진입점은 [`../README.md`](../README.md)입니다.

## 보관 기준

다음 중 하나에 해당하고 이력이 참고 가치가 있을 때만 보관합니다.

- 현재 코드·설정과 맞지 않고 검증된 대체 문서가 있는 경우
- 여러 문서가 하나의 현재 문서로 통합된 경우
- 종료된 기능이나 절차를 설명하는 경우

개인 초안, Git에서 무시되는 문서, `docs/memory/`, `docs/reports/`, `NOTICE.md`, 에이전트 개인 설정, 비밀정보와 생성 산출물은 이 디렉터리에 넣지 않습니다. 현재 안내가 여전히 필요하다면 대체 문서를 먼저 작성·검증한 뒤 기존 문서를 이동합니다.

## 보관 절차

1. 코드와 설정을 확인해 기존 문서가 더 이상 현재 기준이 아님을 검증합니다.
2. 대체 문서를 작성하거나 통합 대상에 유효한 내용을 반영합니다.
3. `git mv`로 원본 이력을 보존해 `docs/archive/`로 이동합니다.
4. 문서 맨 위에 보관일, 보관 사유, 대체 문서가 없으면 기능·정책 종료 사실을 기록합니다.
5. `docs/README.md`와 저장소의 기존 링크를 새 기준 문서로 갱신합니다.
6. Markdown 링크, `git status --short`, `git ls-files docs/archive`를 확인합니다.

보관 문서에는 다음 안내를 추가합니다.

```md
> [!WARNING]
> 이 문서는 현재 개발 기준이 아닌 보관 문서입니다.
>
> - 보관일: YYYY-MM-DD
> - 보관 사유: ...
> - 현재 문서: [`...`](...)
```

## 운영 원칙

- 보관 문서를 현재 구현의 근거로 사용하거나 일반 작업 문서에서 정상 경로로 안내하지 않습니다.
- 보관 후에는 본문을 갱신하지 않고 메타데이터와 깨진 링크만 필요할 때 수정합니다.
- 다시 현재 문서로 사용할 때는 `git mv`로 복원하고 코드와 대조해 전체 내용을 재검증합니다.
- 한 PR에서는 관련 있는 문서 묶음만 이동해 내용 변경과 이동 이력을 리뷰할 수 있게 유지합니다.
